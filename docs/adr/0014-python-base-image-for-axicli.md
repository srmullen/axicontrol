# Python-capable final image, not distroless/static, to host axicli

[ADR-0013](./0013-build-ci-and-publish.md) chose `gcr.io/distroless/static` as the final image stage specifically because the backend compiles to a static, cgo-free Go binary. That reasoning didn't account for `axicli` itself: the AxiDraw CLI ([ADR-0001](./0001-node-pinned-device-access.md), [ADR-0007](./0007-single-backend-service.md)) is a Python tool distributed as `axicli` plus a proprietary `axidrawinternal` wheel, requiring a Python interpreter, libc, and `libusb` — none of which exist in `distroless/static`, which has no libc at all. No mount or sidecar arrangement changes this: a dynamically-linked interpreter cannot execute in a filesystem with no loader or shared libraries, so the `sysinfo` endpoint (and every future endpoint that shells out to `axicli`) could never succeed inside that image, regardless of the device being reachable.

The final stage is `python:3.12-slim` instead, with `libusb-1.0-0` installed via `apt-get` and `axicli` installed via pip from the CDN zip Evil Mad Scientist Laboratories publishes (`https://cdn.evilmadscientist.com/dl/ad/public/AxiDraw_API.zip` — the officially documented install method; it bundles a prebuilt wheel for the closed-source `axidrawinternal` dependency, which isn't otherwise installable). This drops the "smallest practical attack surface, no other runtime dependencies" property ADR-0013 wanted, but that property is moot if the resulting image can't perform the one hardware-facing job this whole service exists for.

## Considered Options

- Keep `distroless/static`, treat `axicli` invocation as a known gap for a follow-up ticket — rejected: the `sysinfo` endpoint is an explicit acceptance criterion of the [backend skeleton ticket](../../tasks/axicontrol-backend-skeleton.md), not a nice-to-have; shipping a container that can structurally never satisfy it isn't a skeleton, it's a stub.
- Sidecar container running `axicli`, called over some IPC from the distroless main container — rejected: adds a process boundary and IPC mechanism to design/secure for a single-pod, single-device system ([ADR-0007](./0007-single-backend-service.md) already rejected splitting this service for the same reason).
- Bind-mount a host-installed Python/axicli into the distroless container — rejected: distroless has no dynamic linker at all, so no mount arrangement of shared libraries makes a dynamically-linked interpreter executable there.
