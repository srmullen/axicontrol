# FileStore abstraction backed initially by a PersistentVolume

Uploaded files are SVG-only — the AxiDraw CLI accepts nothing else, so that part isn't a decision, just a constraint. Storage is a `FileStore` abstraction (put/get/delete behind an interface) rather than coupling the rest of the system directly to one storage technology, with a PersistentVolume mounted into the node-pinned pod ([ADR-0001](./0001-node-pinned-device-access.md)) as the initial adapter. `axicli` needs a real local filesystem path regardless, so a PV avoids a download/upload dance for no benefit at the current scale, while the abstraction leaves room for a future object-storage adapter (e.g. S3-compatible) without touching calling code. The same `FileStore` also backs Pass checkpoint files ([ADR-0008](./0008-checkpoint-file-persistence.md)) — both are SVGs only ever touched by `axicli` in the node-pinned pod, so there was no reason to decide storage twice.

On receipt, uploads are sanitized (AxiDraw layer-option stripping per [ADR-0003](./0003-device-config-and-presets.md); script/event-handler stripping per [ADR-0010](./0010-svg-sanitization-and-img-preview.md)) before being written through the `FileStore`. Retention is indefinite — uploaded SVGs are a personal design library, reusable as the source for future Jobs, and deletion is an explicit user action rather than automatic; storage cost is a non-issue at this scale.
