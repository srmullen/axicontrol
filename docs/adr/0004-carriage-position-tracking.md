# In-memory carriage position tracking for move-to-coordinate

"Testing the axidraw" is two separate features: a hardware self-test/jog panel (`sysinfo`, `cycle`/`toggle`, `align`, `walk_home`) and a per-file plot dry-run that adds `preview`/`report_time` onto the normal Job/Pass/Preset invocation path. The self-test panel needed a "move to coordinate" action, but the AxiDraw CLI has no absolute-position concept or position readback — only relative `walk_x`/`walk_y` deltas and `walk_home` (return to the reference point set when motors were last enabled).

We chose to have axicontrol track the carriage's position itself in memory, zeroed whenever `walk_home` runs or the device is freshly connected/motors enabled (the only reliable reference point the hardware gives), and translate "go to (x, y)" requests into the relative delta needed to get there. This tracking is explicitly best-effort and not persisted: a pod restart loses it until the next home. We accepted that rather than persisting position, since a lost-but-recoverable-by-homing position is a much smaller cost than adding a new durability requirement for a value that's wrong the instant someone jogs the carriage by hand anyway.
